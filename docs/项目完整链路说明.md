# 项目完整链路说明

本文档描述 ExcelCC 从用户访问、前端路由、后端 API、数据库、文件、通知、AI 到部署上线的完整链路。后续维护和扩展时，应先确认改动位于哪一条链路，再决定修改范围。

## 1. 总体链路

```text
用户浏览器
  ↓
Nginx / HTTPS / 静态资源
  ↓
React 前端应用 reace_web
  ↓
API 请求 / 文件请求
  ↓
Spring Boot 后端 excel-forum-backend
  ↓
Service 业务逻辑
  ↓
MyBatis Plus Mapper
  ↓
MySQL / Redis / 上传文件目录
```

关键原则：

- 前端负责交互体验，不负责最终权限、判题、奖励和安全决策。
- 后端负责认证、授权、业务规则、幂等、限流、数据一致性。
- 数据库负责持久化业务状态，不通过前端状态推导真实结果。
- 文件必须通过受控上传、下载、预览和回收站链路管理。

## 2. 前端访问链路

用户访问 `https://www.excelcc.cn/` 后：

1. Nginx 返回前端静态资源。
2. React 入口加载 `reace_web/src/main.tsx`。
3. `App.tsx` 挂载路由。
4. `routes.tsx` 根据 URL 懒加载对应页面。
5. 页面通过 `src/app/lib` 中的 API 封装请求后端。
6. 数据进入页面组件、业务组件和交互组件。

主要前台路由：

- `/`：首页。
- `/practice`：小试牛刀章节入口。
- `/practice/question/:id`：答题页。
- `/practice/result/:id`：答题结果页。
- `/tutorials`：教程中心。
- `/templates`：模板中心。
- `/qa`：求助答疑。
- `/qa/my`：我的答疑。
- `/qa/cases/:id`：求助详情。
- `/tools`：实用工具。
- `/assistant`：AI 助手页面。
- `/notifications`：通知中心。
- `/profile`：用户中心。

主要后台路由：

- `/admin/overview`：后台总览。
- `/admin/users`：用户管理。
- `/admin/questions`：题库管理。
- `/admin/question-categories`：题目分类。
- `/admin/templates`：模板中心管理。
- `/admin/qa`：答疑管理。
- `/admin/assistant`：AI 助手配置。
- `/admin/file-recycle-bin`：文件回收站。

## 3. 登录与权限链路

```text
登录/注册页面
  ↓
/api/auth/**
  ↓
AuthController
  ↓
认证 Service + 密码校验 + 限流
  ↓
JWT 签发
  ↓
前端保存 token
  ↓
后续 API 携带 Authorization
  ↓
后端 Security 校验用户与角色
```

维护要求：

- 登录成功后应返回用户原本要访问的页面，不默认回首页。
- 普通用户访问后台接口必须由后端拒绝。
- 管理员权限必须以后端角色校验为准。
- 前端隐藏按钮只是体验优化，不是安全边界。
- 用户资源必须校验归属，例如答题记录、QA 求助、答疑文件。

## 4. 小试牛刀做题链路

```text
/practice
  ↓
章节与题目列表 API
  ↓
用户进入 /practice/question/:id
  ↓
加载题目、模板快照、用户可作答区域
  ↓
Excel 编辑器作答
  ↓
提交答案
  ↓
Practice Service 判题
  ↓
记录答题结果、进度、首次通过奖励
  ↓
/practice/result/:id 展示结果
```

维护重点：

- 用户态题目接口不得提前返回标准答案、解析和隐藏判题字段。
- 判题和计分必须由后端完成。
- 答题提交必须限流，并保证奖励幂等。
- 客户端耗时只能作为参考，不能作为可信成绩依据。
- 题目列表状态要以后端进度为准，前端只做及时刷新。

## 5. Excel 模板与编辑器链路

```text
后台上传 Excel 模板
  ↓
后端上传校验与保存
  ↓
前端模板编辑器读取 workbook 快照
  ↓
管理员选择答题工作表、答题区域、标准答案、判题规则
  ↓
保存题目配置
  ↓
用户答题页加载可作答模板
  ↓
用户提交 workbook snapshot
  ↓
后端按规则判题
```

关键数据：

- 模板文件路径。
- 工作表名称。
- 答题区域。
- 标准答案。
- 判题模式。
- 动态数组规则。
- 日期、文本、百分比等格式信息。
- 理想答案参考图。

维护重点：

- 上传模板不能丢失工作表、公式、日期格式和空白结构。
- 动态数组公式必须保留锚点公式，不能保存溢出子格为阻塞值。
- 在线编辑器不是完整 Excel 365/WPS 引擎，复杂公式要优先保证公式保存和判题一致性。
- 删除键、Esc、公式栏拖拽、格式设置都属于编辑器基础交互，改动后必须回归验证。

## 6. 教程链路

```text
/tutorials
  ↓
教程列表 API
  ↓
教程详情页面
  ↓
函数目录、正文、公式块、示例表格、右侧学习辅助
  ↓
关联练习入口
```

维护重点：

- 教程正文渲染不得破坏原始内容读取。
- 公式块和表格样式属于展示增强，不改变后端数据结构。
- 关联练习跳转要保持现有路由兼容。

## 7. 模板中心链路

```text
/templates
  ↓
模板列表与筛选
  ↓
模板详情/预览/下载
  ↓
后端校验权限、限流、记录下载
  ↓
返回受控文件流
```

后台链路：

```text
/admin/templates
  ↓
新增/编辑模板
  ↓
上传模板文件和预览图
  ↓
保存模板元数据
  ↓
前台展示
```

维护重点：

- 模板下载必须限流。
- 删除模板文件必须进入文件回收站。
- 不直接暴露敏感 Excel 的 raw URL。

## 8. QA 求助答疑链路

```text
/qa
  ↓
用户发起案例求助
  ↓
填写标题、需求描述、理想答案区域、上传 Excel
  ↓
其他用户查看求助详情
  ↓
在线作答或下载模板作答
  ↓
提交答疑 Excel 文件
  ↓
系统通知求助发起人
  ↓
发起人采纳后求助显示已答疑
```

我的答疑链路：

```text
/qa/my
  ↓
我发起的求助
  ↓
我提交的答疑
  ↓
我的解题分享
```

维护重点：

- QA 只做求助、答疑文件、解题分享，不扩展评论、私信、帖子。
- 答疑者最终提交的是 Excel 文件。
- 删除求助或答疑应软删除，并进入文件回收站策略。
- 答疑通知只推送给求助发起人。

## 9. AI 助手链路

```text
AI 助手入口 / 编辑器内助手
  ↓
前端发送文本、图片或附件
  ↓
/api/assistant/**
  ↓
后端读取管理员配置
  ↓
调用配置的模型服务
  ↓
记录调用统计
  ↓
返回对话结果
```

后台配置链路：

```text
/admin/assistant
  ↓
配置 URL、SK、模型、推理等级、超时时间、system prompt
  ↓
保存为默认配置或单位配置
```

维护重点：

- system prompt 以后台配置为准。
- 超时时间、模型、推理等级由管理员配置。
- 图片识别和附件请求要受上传限制和 AI 调用限流保护。
- AI 失败要返回用户可理解的提示，不展示网关 HTML 或堆栈。

## 10. 通知链路

```text
业务事件发生
  ↓
Notification Service 创建通知
  ↓
用户顶部通知 / 通知中心读取
  ↓
点击通知跳转业务页面
  ↓
已读、删除、批量处理
```

当前通知应围绕：

- 系统通知。
- 做题结果或进度。
- 教程或模板相关提示。
- QA 答疑通知。
- AI 助手和后台相关通知。

维护重点：

- 通知组件只负责展示和跳转，不承载业务规则。
- 通知跳转要直达目标页面，返回逻辑应回到用户原始位置。
- 已下线业务通知不得重新引入旧功能入口。

## 11. 文件上传、下载与回收站链路

```text
上传文件
  ↓
文件大小、类型、签名、Excel 复杂度校验
  ↓
保存到受控目录
  ↓
业务表保存文件引用
  ↓
下载或预览时通过业务接口鉴权
```

删除链路：

```text
业务删除
  ↓
业务记录软删除
  ↓
文件移动到回收站目录
  ↓
写入 file_recycle_item
  ↓
管理员可恢复或彻底删除
  ↓
超过保留期定时清理
```

维护重点：

- 上传接口不能接收无限大小文件。
- 下载接口必须限流。
- 文件删除不能直接物理删除。
- 恢复时要恢复业务记录和文件引用。
- 自增 ID 不重排、不复用。

## 12. 后台管理链路

```text
/admin/**
  ↓
前端后台路由
  ↓
AdminLayout 鉴权体验
  ↓
/api/admin/**
  ↓
后端管理员角色校验
  ↓
独立 Admin Controller
  ↓
Service 业务管理逻辑
```

后台模块应覆盖：

- 总览统计。
- 用户与单位。
- 通知管理。
- 题库管理。
- 题目分类。
- 模板中心。
- 积分体系。
- 等级体系。
- AI 助手。
- QA 管理。
- 文件回收站。

维护重点：

- 后台接口不能依赖前端菜单隐藏来保护。
- 所有可编辑列表要有筛选、分页、批量操作和误操作确认。
- 关键操作要留下审计或可追溯记录。

## 13. 部署链路

```text
本地代码
  ↓
typecheck / test / build / mvn test
  ↓
提交并推送 GitHub main
  ↓
生产服务器 /www/wwwroot/excelcc/kick-deploy/repo 拉取
  ↓
bash scripts/deploy/production-deploy.sh
  ↓
构建前端 dist
  ↓
构建后端 JAR
  ↓
备份当前线上版本
  ↓
更新 /www/wwwroot/excelcc/kick-web
  ↓
更新 /www/wwwroot/excelcc/kick-backend
  ↓
重启服务并健康检查
  ↓
更新 ONLINE_UPDATE_LOG.md
```

维护重点：

- 不整目录覆盖线上项目。
- 不触碰其他项目目录。
- 部署前阅读 `ONLINE_UPDATE_LOG.md`。
- 部署后验证首页、公共接口、做题、教程、模板、QA、AI。
- 失败时以服务器备份路径回滚。

## 14. 一次请求的排查路径

排查线上问题时按以下顺序缩小范围：

1. 浏览器控制台是否有 JS 错误或网络错误。
2. 前端请求 URL、方法、状态码和响应体是否正确。
3. 后端 Controller 是否收到请求。
4. 鉴权和角色是否通过。
5. Service 是否命中业务校验、限流或幂等。
6. Mapper SQL 和数据库数据是否符合预期。
7. 文件路径、权限、回收站状态是否正确。
8. Nginx、后端服务、MySQL、Redis 是否有资源瓶颈。
9. 是否是浏览器缓存或旧静态资源未刷新。

## 15. 常见变更影响范围

| 变更类型 | 必查链路 |
| --- | --- |
| 登录跳转 | 前端路由、Auth API、token 保存、来源页恢复 |
| 答题判题 | 题目接口、编辑器快照、判题 Service、奖励幂等 |
| Excel 上传 | 上传接口、文件校验、workbook 解析、编辑器预览 |
| 动态数组公式 | 公式锚点、溢出区域、答案快照、判题结果 |
| 模板下载 | 权限校验、限流、文件路径、下载统计 |
| QA 答疑 | QA API、文件上传、通知、采纳状态 |
| AI 回复 | 后台配置、模型接口、超时、附件、统计 |
| 通知跳转 | 通知类型、目标 URL、已读状态、返回逻辑 |
| 后台列表 | 筛选、分页、批量操作、管理员鉴权 |
| 文件删除 | 软删除、回收站、恢复、彻底删除 |
