# 模块分工开发模式

本文档定义 ExcelCC 多会话并行开发时的默认协作方式。目标是让每个会话只处理一个模块或一组强相关改动，减少在 `main`、公共路由、部署记录和共享配置上的冲突。

## 1. 基本规则

- `main` 是集成和发布基线，不作为长期功能开发区。
- 每个模块或功能会话使用独立 Git worktree 和独立分支。
- 分支命名统一使用 `codex/<module>-<feature>`，例如 `codex/frontend-admin-users-filter`。
- 本地 worktree 统一放在 `.worktrees/`，该目录已加入 `.gitignore`，不提交进仓库。
- 一个会话默认只拥有一个模块范围；需要跨模块修改时，先在任务开头声明影响面。
- 涉及线上部署时才更新 `ONLINE_UPDATE_LOG.md`，普通功能分支不要提前修改线上更新记录。

## 2. 创建模块 worktree

从仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev\new-module-worktree.ps1 -Module frontend-admin -Feature users-filter
```

脚本会：

1. 确认当前主工作区 clean。
2. 确认 `.worktrees/` 已被 Git 忽略。
3. 拉取最新 `origin` 引用。
4. 基于 `origin/main` 创建 `codex/<module>-<feature>` 分支。
5. 在 `.worktrees/<module>-<feature>/` 创建隔离工作区。

如果只想预览将创建的分支和路径：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev\new-module-worktree.ps1 -Module backend-practice -Feature grading-rule -DryRun
```

## 3. 建议模块边界

- `frontend-public-*`：前台首页、教程、模板、QA、AI、个人中心。
- `frontend-admin-*`：后台管理页面和后台组件。
- `backend-api-*`：Controller、DTO、Service、Mapper、权限校验。
- `backend-data-*`：Flyway migration、数据修复、索引、归档。
- `excel-editor-*`：Excel 编辑器、导入导出、判题快照、动态数组。
- `deploy-docs-*`：部署脚本、运维文档、线上记录。

模块名可以按实际任务细化，但不要把不相关功能塞进同一个分支。

## 4. 高冲突文件

以下文件容易被多个会话同时修改，开发前需要明确归属：

- `AGENTS.md`
- `CLAUDE.md`
- `docs/README.md`
- `ONLINE_UPDATE_LOG.md`
- `reace_web/src/app/routes.tsx`
- `reace_web/src/app/lib/` 下的公共 API 和工具文件
- `reace_web/package.json`
- `reace_web/package-lock.json`
- `excel-forum-backend/pom.xml`
- `excel-forum-backend/src/main/resources/db/migration/`
- `scripts/deploy/`
- `scripts/quality/`

同一时间只让一个会话修改同一个高冲突文件。其他会话如确实需要改动，应先同步最新分支并说明原因。

## 5. 每个会话开始前

1. 确认自己所在路径是对应 worktree，而不是仓库根目录主工作区。
2. 执行 `git status -sb`，确认当前分支是 `codex/<module>-<feature>`。
3. 阅读 `AGENTS.md`、`docs/开发规范.md`、`docs/项目文件结构说明.md` 和必要的链路/部署文档。
4. 只修改当前任务范围内的文件。

## 6. 每个会话结束前

1. 执行与改动范围匹配的验证命令。
2. 执行 `git status -sb`，确认没有无关生成物。
3. 汇报分支名、worktree 路径、修改范围、验证结果和未完成风险。
4. 需要合并时，从最新 `origin/main` 重新同步，解决冲突后再进入集成。

## 7. 集成和部署

- 功能分支完成后先合并到 `main` 或通过 PR 合并，不直接从多个功能分支分别部署生产。
- 部署只从 `main` 进行，生产服务器 `deploy.env` 当前使用 `BRANCH="main"`。
- 标准部署入口仍是 `/www/wwwroot/excelcc/kick-deploy/repo` 下的 `bash scripts/deploy/production-deploy.sh`。
- 部署成功后按 `ONLINE_UPDATE_LOG.md` 的格式在顶部追加记录。

## 8. 当前后台模块重构并行分支

本轮后台模块重构固定从同一个 `main` 基线创建分支和 worktree。每个会话只进入自己的 worktree，不在主工作区直接开发。

| 模块 | 分支 | Worktree | 主要边界 |
| --- | --- | --- | --- |
| 题库管理模块 | `codex/admin-question-bank-refactor` | `.worktrees/admin-question-bank-refactor` | 题库列表、题目新增/编辑、Excel 模板题配置、题目批量操作 |
| 题目分类模块 | `codex/admin-question-categories-refactor` | `.worktrees/admin-question-categories-refactor` | 分类树、排序、启停、分类与题目数量展示 |
| 模板中心模块 | `codex/admin-template-center-refactor` | `.worktrees/admin-template-center-refactor` | 后台模板列表、上传、预览、下载配置、模板批量操作 |
| 积分体系模块 | `codex/admin-points-refactor` | `.worktrees/admin-points-refactor` | 积分规则、积分流水、奖励配置、幂等展示 |
| 等级体系模块 | `codex/admin-levels-refactor` | `.worktrees/admin-levels-refactor` | 等级规则、等级映射、经验阈值、用户等级展示联动 |
| AI 助手模块 | `codex/admin-ai-assistant-refactor` | `.worktrees/admin-ai-assistant-refactor` | AI 配置、模型列表、prompt、超时、调用统计 |
| 答疑管理模块 | `codex/admin-qa-refactor` | `.worktrees/admin-qa-refactor` | QA 求助、答疑、采纳、反馈、后台管理 |
| 文件回收站模块 | `codex/admin-file-recycle-refactor` | `.worktrees/admin-file-recycle-refactor` | 文件回收站列表、恢复、彻底删除、过期清理 |
| 集成会话 | `codex/admin-module-integration` | `.worktrees/admin-module-integration` | 合并上述分支、解决冲突、跑全量测试、最终回归 |

### 8.1 共享文件归属

以下文件默认只允许集成会话修改。模块分支如必须修改，结束报告中必须明确说明原因和冲突点：

- `reace_web/src/app/routes.tsx`
- `reace_web/src/app/pages/AdminLayout.tsx`
- `reace_web/src/app/pages/AdminConsoleTypes.ts`
- `reace_web/src/app/pages/AdminConsoleForms.tsx`
- `reace_web/src/app/admin/shared.ts`
- `reace_web/src/app/lib/api.ts`
- `excel-forum-backend/src/main/resources/db/migration/`
- `scripts/deploy/`
- `scripts/quality/`
- `ONLINE_UPDATE_LOG.md`

模块分支优先创建或修改模块私有文件，例如 `AdminQuestions.tsx`、`AdminTemplateCenter.tsx`、`AdminQa.tsx`、对应 `*.test.ts` 和后端独立 Controller/Service/DTO。不要把模块逻辑塞回共享布局或大控制器。

### 8.2 Flyway 迁移版本分配

如果模块确实需要数据库结构变更，使用以下预留版本区间，避免多个分支都新增同一个版本号。没有数据库变更时不要新增 migration。

| 模块 | 版本区间 |
| --- | --- |
| 题库管理模块 | `V70` - `V74` |
| 题目分类模块 | `V75` - `V79` |
| 模板中心模块 | `V80` - `V84` |
| 积分体系模块 | `V85` - `V89` |
| 等级体系模块 | `V90` - `V94` |
| AI 助手模块 | `V95` - `V99` |
| 答疑管理模块 | `V100` - `V104` |
| 文件回收站模块 | `V105` - `V109` |

迁移必须只新增文件，不修改历史 migration。跨模块共用字段由集成会话统一创建，避免模块分支互相猜测。

### 8.3 每个模块分支必须遵守

1. 开始前执行 `git status -sb`，确认在自己的 `codex/admin-*-refactor` 分支。
2. 阅读 `AGENTS.md`、`docs/开发规范.md`、`docs/项目文件结构说明.md`、`docs/项目完整链路说明.md`。
3. 只处理本模块 UI、API、DTO、Service 和测试，不顺手重构其他模块。
4. 不修改 `ONLINE_UPDATE_LOG.md`，不上线部署。
5. 不提交 `dist/`、`target/`、`node_modules/`、上传文件、日志、临时截图。
6. 所有新增可编辑列表必须考虑筛选、分页、批量选择、批量删除或批量状态操作边界。
7. 后端新增写接口必须有 DTO 校验、权限校验、资源归属校验和失败状态码测试。
8. 前端新增复杂交互必须至少补纯函数或组件行为测试；没有可测抽象时先抽出可测 view-model。
9. 分支结束前至少运行与模块相关的前端测试/构建或后端测试；改动跨前后端时两边都要跑。
10. 结束报告必须包含：分支名、worktree 路径、修改范围、验证命令、是否涉及 migration、是否触碰共享文件、未完成风险。

### 8.4 集成会话规则

集成会话由 `codex/admin-module-integration` 承担，负责：

1. 从最新 `origin/main` 创建或重置集成分支。
2. 按模块风险从低到高逐个合并功能分支，每合并一个分支先处理冲突，再运行该模块最小验证。
3. 统一处理共享文件冲突，例如后台侧边栏、路由、公共类型、公共 API 封装。
4. 统一处理 Flyway 版本、重复 DTO、重复工具函数和重复 UI 组件。
5. 合并完成后运行完整质量门禁：`powershell -ExecutionPolicy Bypass -File scripts\quality\check.ps1`。
6. 全量通过后才合并回 `main`，再按部署流程上线。

如果任一模块分支未通过验证或冲突涉及业务判断，集成会话不强行猜测，先退回该模块修复。
