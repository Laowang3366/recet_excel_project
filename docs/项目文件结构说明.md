# 项目文件结构说明

本文档说明 ExcelCC 仓库内主要目录、文件职责和后续维护时的放置规则。新功能、新文档和重构文件应优先遵循本文档，避免再次出现目录膨胀、临时文档堆积和模块边界混乱。

## 1. 根目录结构

```text
recet_excel_project/
├─ excel-forum-backend/     后端 Spring Boot 应用
├─ reace_web/               前端 React + Vite 应用
├─ docs/                    长期有效的项目文档
├─ scripts/                 本地、部署、压测和维护脚本
├─ .github/                 GitHub Actions 与仓库自动化配置
├─ .vscode/                 本地编辑器配置
├─ AGENTS.md                AI/协作代理执行约束
├─ CLAUDE.md                其他协作工具约束
├─ README.md                项目总入口说明
├─ SECURITY.md              安全注意事项
└─ ONLINE_UPDATE_LOG.md     线上部署和变更记录
```

根目录只保留跨工具、高频入口和生产上线必须读取的文件。新增长期文档默认放入 `docs/`，一次性计划和历史方案放入 `docs/archive/`。

以下目录或文件视为生成物、运行物或临时产物，不应手工改源码：

- `reace_web/dist/`
- `reace_web/node_modules/`
- `excel-forum-backend/target/`
- `excel-forum-backend/uploads/`
- `run-logs/`
- `tmp/`
- `tmp_browser_debug/`
- `*.log`

## 2. 后端目录结构

后端应用位于 `excel-forum-backend/`。

```text
excel-forum-backend/
├─ src/main/java/com/excel/forum/
│  ├─ config/        跨模块配置
│  ├─ controller/    HTTP API 入口
│  ├─ entity/        数据库实体
│  ├─ mapper/        MyBatis Plus 数据访问
│  ├─ security/      认证、授权、JWT、登录安全
│  ├─ service/       业务逻辑、事务、限流、文件流转
│  ├─ util/          通用低依赖工具
│  └─ ForumApplication.java
├─ src/main/resources/
│  ├─ db/migration/  Flyway 数据库迁移
│  ├─ application.yml
│  └─ application-dev.yml
└─ src/test/java/    JUnit、MockMvc、Service 测试
```

### 2.1 Controller 放置规则

`controller/` 只处理请求入口：

- 参数接收和基础校验。
- 读取当前登录用户和角色。
- 调用 Service。
- 返回统一响应。

禁止在 Controller 中写复杂业务规则、事务、文件移动、奖励结算或跨模块状态同步。

常见 Controller 分组：

- `AuthController`：登录、注册、找回密码。
- `PracticeController`、`PracticeCampaignController`：做题和闯关。
- `TutorialController`：教程读取。
- `TemplateCenterController`：模板中心。
- `QaController`：求助答疑。
- `AssistantController`：AI 助手。
- `NotificationController`：通知。
- `Admin*Controller`：后台管理入口。

新增后台模块时优先新增独立 `AdminXxxController`，不要继续扩大通用后台 Controller。

### 2.2 Service 放置规则

`service/` 是业务规则所在地：

- 鉴权后仍需校验资源归属。
- 写操作事务边界。
- 幂等键、限流、积分奖励、审计日志。
- 文件回收站、上传下载、Excel 安全检查。
- 通知创建和业务状态变更。

一个 Service 应围绕一个业务能力组织。跨模块流程可以建立协调型 Service，但不要让单个 Service 同时承担题库、QA、模板、AI、通知等多个业务。

### 2.3 Entity 与 Mapper 放置规则

- `entity/` 只映射数据库表字段，不放请求字段和页面展示字段。
- `mapper/` 只写数据查询和更新，不写业务判断。
- 复杂查询优先封装成明确方法名，避免 Controller 或 Service 内拼接无意义条件。

### 2.4 Migration 放置规则

数据库变更统一放在：

```text
excel-forum-backend/src/main/resources/db/migration/
```

规则：

- 只能新增 migration，禁止修改历史 migration。
- 命名使用 `V数字__说明.sql`。
- 新增字段要考虑默认值、历史数据回填和索引。
- 删除业务数据表前必须先有归档和备份方案。

## 3. 前端目录结构

前端应用位于 `reace_web/`。

```text
reace_web/
├─ src/
│  ├─ app/
│  │  ├─ admin/       后台专用组件或子模块
│  │  ├─ components/  前台和通用组件
│  │  ├─ lib/         API、工具函数、Excel 工具、状态工具
│  │  ├─ pages/       路由页面
│  │  ├─ App.tsx
│  │  └─ routes.tsx
│  ├─ styles/         全局样式
│  └─ main.tsx        前端入口
├─ index.html
├─ package.json
└─ vite.config.ts
```

### 3.1 pages

`src/app/pages/` 放路由页面。页面职责是：

- 页面级取数。
- 页面布局。
- 路由参数解析。
- 页面内弹窗状态协调。

页面不应承载复杂业务算法、Excel 序列化细节、下载鉴权、权限判断或多模块数据同步。

### 3.2 components

`src/app/components/` 放可复用组件：

- 顶部导航、布局、通知弹层、AI 助手入口。
- Excel 编辑器包装组件。
- 表格、筛选器、弹窗、上传区域。
- 跨页面复用的展示组件。

组件应通过 props 接收数据和回调，避免直接写死某个页面的业务流程。

### 3.3 admin

`src/app/admin/` 放后台专用组件或后台复杂页面拆分出的子模块。后台模块要保持“列表、筛选、编辑弹窗、批量操作”边界清楚，避免所有功能堆在单个页面文件里。

### 3.4 lib

`src/app/lib/` 放低耦合逻辑：

- API 请求封装。
- React Query key。
- Excel workbook 导入、导出、序列化、快照处理。
- 日期、数字、文本格式化。
- 权限和登录跳转工具。

Excel 相关工具必须保持可测试。动态数组、日期格式、删除键、Esc 退出、公式栏等问题修复时，优先在 `lib` 层补最小复现测试。

### 3.5 routes.tsx

`routes.tsx` 只维护路由和懒加载关系，不写页面业务逻辑。新增页面要确认：

- 是否需要登录。
- 是否属于前台还是后台。
- 是否需要保留登录后回跳。
- 是否会影响顶部导航、头像菜单或通知跳转。

## 4. docs 目录结构

`docs/` 只保留仍有执行价值的长期文档。

```text
docs/
├─ README.md                         文档索引
├─ development-guidelines.md         项目开发规范
├─ 项目文件结构说明.md
├─ 项目完整链路说明.md
├─ deployment-operations.md          部署与运维
├─ performance-load-testing.md       压测说明
├─ runtime-tuning.md                 运行参数调优
├─ database-performance.md           数据库性能诊断
├─ maintenance/                      发布、评审、维护清单
├─ security/                         安全审查和修复记录
└─ archive/                          历史方案、过期计划、旧审计
```

文档维护原则：

- 根目录不再堆积新方案文档。
- 临时排查记录完成后要归档或删除。
- 安全、性能、部署类文档要写清验证命令。
- 不在文档中记录密码、Token、数据库连接串和服务器凭据。

## 5. scripts 目录结构

`scripts/` 放可重复执行的脚本：

- 部署脚本。
- 压测脚本。
- 质量检查脚本。
- 迁移或维护脚本。

脚本必须具备明确入口、参数说明和失败退出码。涉及生产的脚本要避免硬编码密码和服务器凭据。

## 6. 文件放置决策表

| 场景 | 应放位置 |
| --- | --- |
| 新增前台页面 | `reace_web/src/app/pages/` |
| 新增后台页面 | `reace_web/src/app/pages/` 或拆分到 `reace_web/src/app/admin/` |
| 新增可复用 UI | `reace_web/src/app/components/` |
| 新增 API 封装或工具函数 | `reace_web/src/app/lib/` |
| 新增业务接口 | `excel-forum-backend/src/main/java/com/excel/forum/controller/` |
| 新增业务规则 | `excel-forum-backend/src/main/java/com/excel/forum/service/` |
| 新增数据库表或字段 | `excel-forum-backend/src/main/resources/db/migration/` |
| 新增长期说明文档 | `docs/` |
| 新增发布或评审清单 | `docs/maintenance/` |
| 新增安全审查文档 | `docs/security/` |
| 新增过期方案归档 | `docs/archive/` |
| 新增部署或维护脚本 | `scripts/` |

## 7. 禁止事项

- 禁止把业务逻辑写进路由文件。
- 禁止让前端控制权限、奖励、判题最终结果。
- 禁止把答案、解析、隐藏字段提前返回给用户态页面。
- 禁止直接删除上传文件，文件型业务删除必须走回收站。
- 禁止手工修改构建产物、依赖目录、运行日志和上传目录。
- 禁止把一次性计划继续放在根目录。
- 禁止在新增功能时复用已下线旧业务命名，避免后续维护误判。
